# 2026-10-27 — PR #396 second review: fingerprint scheme, grow-after-check, exact registrants (LFXV2-2770)

**Fix** — bot review findings after main was merged into the branch.

- `audience.SelectionFingerprint` hashes a scheme marker (`direct-exclusions-v2`). A selection whose
  resolved exclusions equal the requested ones tagged the same as a pre-LFXV2-2770 master that
  excluded a combined wrapper list, so a repeat could reuse a master whose wrapper was edited or
  deleted. The first such compose after deploy creates a new master once.
- `resolveSuppressions` reads, obtains (including lists RECOVERED after a refused or unconfirmed
  create) and checks every standing list against the inclusions before it verifies the
  registrants list or grows the standing list, so a request later refused with the overlap 400 no
  longer grows the list every audience in the project excludes.
- `audience.RegistrantsListMatches` rejects a filter that sets `includeObjectsWithNoValueSet`.
- A yearless `current_registrants_event` is an `audience.FieldError`, a 400 naming the field and the
  year requirement, instead of the generic invalid-request text.
- The custom interpreter adds past editions to the event's default audience only when one of the
  page-view URLs is the event page itself (`selectsPage`), not for any page-view audience.
- Docs: compose's `suppression` changed meaning (it was the combined list covering every
  exclusion); the Goa description and `docs/api-catalog.md` now call it a breaking change and
  point at `suppression_list_ids`. lfx-self-serve is its only client.
