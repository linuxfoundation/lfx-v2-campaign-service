# 2026-11-17 — #563 Microsoft shared-list and criterion responses refuse duplicated keys

**Fix** — A #617 review finding raised by Copilot and Greptile. `encoding/json` decodes a key declared twice without error, and the last spelling wins, including a case variant. A `SetSharedEntityAssociations` 200 such as `{"PartialErrors":[{"Index":0,"Code":1234,"Code":0}]}` therefore decoded as the zero-code placeholder. The refused list was reported APPLIED, and the campaign could stay `created` instead of `created_degraded`. The `GetSharedEntities` pre-create read had the same gap: `{"Id":9,"Id":4001}` or `{"Type":"PlacementExclusionList","type":"NegativeKeywordList"}` could make the check accept a list whose identity the bytes do not state unambiguously.

Both decode sites in `shared_negative_lists.go` now go through `decodeTrusted`, which runs `identityjson.Check` before decoding. A refused association response follows the existing unreadable-response path: every list is UNCONFIRMED and the campaign is degraded. A refused lookup returns the existing `errSharedListLookupMalformed` error ("not the documented shape"), so the job fails before anything is created.

The ad schedule and bid adjustments added in this PR send their criteria through `postCampaignCriterions` (`geo.go`). It decoded `NestedPartialErrors` the same way, so a duplicated `Code` could turn a rejection into padding, and the step would report the criteria as attached. That decode now uses `decodeTrusted` too, and a refusal maps to `errNoID`, which means UNCONFIRMED. Structured snippets and the logo extension already decode through `adExtensionIdentity`, `mediaIdentity` and `associateCampaignExtension`, which use `decodeTrusted`. The search-network setting adds no decoder.

Covered by new cases in `TestAttachCampaignSharedNegativeKeywordLists_Outcomes`, `TestCheckSharedNegativeKeywordLists_Refusals`, `TestCreateCampaign_CriterionErrorEntriesUseTheDefaultCodeRule`, and `TestMicrosoftSharedNegativeLists_AssociationShortfallDegrades`, and by the new `TestMicrosoftSharedNegativeLists_DuplicateKeyLookupCreatesNothing`.
