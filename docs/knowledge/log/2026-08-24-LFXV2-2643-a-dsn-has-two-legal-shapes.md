# 2026-08-24 — a DSN has two legal shapes, and a URL-shaped redactor sees one

**Fix** — `dbtest.SafeDSNErr` leaked the DSN's identifiers for the third time, and the
third arm was the one no URL-shaped rule could reach.

The first two rounds were both about a `*url.Error`: `%v` on one embeds the whole DSN, and
unwrapping to its cause still quotes the fragment `net/url` choked on. Both were closed by
withholding. Both left the fallback arm — every error that is NOT a `*url.Error` — reading
`redact.URLUserinfo(err.Error())`.

`redact.URLUserinfo` understands only URL-shaped `user:pass@` text. A DSN has a second legal
shape. pgx accepts KEYWORD/VALUE connection strings (`host=h user=u password=p dbname=d`) and
builds its errors out of that shape, so the redactor passed them through untouched. Verified
against pgx v5.9.2 with a placeholder credential: a keyword DSN carrying `password=` came back
verbatim — the password too, not only the username the review named.

Two INDEPENDENT channels put the identifiers there, which is the part that decides the fix:

- pgx SPLICES the DSN into its own messages. `*pgconn.ConnectError` formats
  ``failed to connect to `user=%s database=%s` `` straight from `Config`; `*pgconn.ParseConfigError`
  prints the whole connection string through pgx's own `redactPW`, which masks `password=` and
  userinfo but KEEPS the username in every branch. Neither unwraps to a `*url.Error`, so the
  arm that handles those never sees them.
- PostgreSQL QUOTES the identifiers back in its own diagnostics, with no involvement from the
  DSN's formatting at all: `role "u" does not exist` (28000), `database "d" does not exist`
  (3D000), `password authentication failed for user "u"` (28P01).

The second channel is why scrubbing pgx's two templates was rejected. That is a denylist, and
the text it would have to match is generated by the SERVER, so no amount of template-matching
on our side anticipates it — the same failure mode that produced rounds one and two.

So the test moved from SHAPES to VALUES. `pgconn.ParseConfig` reads both DSN forms into one
`Config`, giving the user, password, database and host actually configured; if the rendered
message contains any of them, it is replaced WHOLESALE with a sentinel. This is the discipline
`internal/infrastructure/config`'s `redactDatabaseURL` already applies to the same value class,
for the same stated reason.

Wholesale, not surgical. Excising the matched bytes is its own defect: an identifier may be
short or ordinary (`app`, `a`, a database named `connection`), and cutting it out of the
driver's prose corrupts the diagnosis — trading a leak for an unreadable log rather than
fixing either.

Diagnosability survives because a message naming NO configured identifier keeps its text in
full, which is the common case: `connection refused`, `password authentication failed`,
`does not exist` name the fault without naming the credential.

**Verification** — nine mutations, four SURVIVED the first table and each marked a real gap.
Dropping `cfg.Host` or `cfg.Password` from the compared set survived because every realistic
pgx message names several identifiers at once, so no single comparison was load-bearing; that
needed cases naming ONE identifier each. Failing OPEN on an unparseable DSN survived because
no case drove one. Dropping the `id != ""` guard survived because every case populated every
field — and that mutation is the dangerous one: `strings.Contains(msg, "")` is true for every
string, so a peer-auth DSN with no password would withhold EVERY error the package prints. All
nine are killed now.

**Note** — the pre-existing `TestSafeDSNErrKeepsDriverTextForNonURLErrors` was environment-
dependent by accident. It documents itself as needing no database, but SafeDSNErr now compares
against the configured DSN, and the test's fixtures say `host=localhost` — so a runner whose
`TEST_DATABASE_URL` also says `localhost` saw the helper correctly withhold a message naming
the configured host, and the test read that as a regression. It now pins a DSN sharing no
identifier with its fixtures. The pin does not weaken it: the constant-fallback mutation it
exists to catch is still caught.

The same leak is live on the PRODUCTION path — `postgres.Migrate` → `pool.go` → `container.go`
writes the DSN to the pod log at startup and on every retry — and is tracked by issue #178.
This change is test-only and deliberately does not touch it, but the shape transfers: production
holds the DSN it dialled, so it can run the same value-keyed comparison without reading the
environment.

**Fix** — the first cut of this made the redaction read `TEST_DATABASE_URL` inside the
helper, and that was the wrong seam. Reading the environment is the CALLER's convenience,
not a property of the redaction, and baking it in forced every test of the behaviour to pin
the value with `t.Setenv` — which mutates process-global state, so Go forbids it in a test
with parallel ancestors. Bugbot caught the immediate symptom: subtests still called
`t.Parallel()` under a parent that had become serial.

Its stated mechanism was wrong — it claimed `Parallel` walks ancestors for `denyParallel`
and that the suite panics. Checking `testing.go`: `Setenv` sets `denyParallel` on `t` ALONE,
`Parallel` tests only its own `t`, and the ancestor walk runs the other way (`Setenv` looks
UP for `isParallel`). Nothing panicked, and the suite was green. The conclusion was right
anyway, for a reason it did not give: a serial test that sets the variable runs concurrently
with this file's PARALLEL tests, which read the same variable through `DSN()`. `Cleanup`
restores it, so the window is invisible in a green run and would surface only as a flake.

So the fix was to remove the shared mutable state rather than to serialise more tests.
`SafeDSNErrFor(dsn, err)` takes the DSN explicitly and holds the logic; `SafeDSNErr(err)` is
a one-line wrapper passing `DSN()`. Every test now names the DSN it means, uses no `Setenv`,
and is parallel again.

That refactor introduced one new untested seam, and the mutation sweep found it: replacing
`DSN()` with `""` in the wrapper compiles, keeps all nine explicit-DSN tests green, and
silently restores the verbatim passthrough on the ONLY path the harness actually calls.
`TestSafeDSNErrReadsTheConfiguredDSN` closes it — the single test in the file that touches
the environment, deliberately serial and asserting the wiring rather than the redaction.
All ten mutations are killed.

**Note** — a reviewer's conclusion can be correct while its proof is not. The proof was
checkable against `testing.go` in a minute, and checking it changed the fix: had the panic
claim been taken at face value, the repair would have been "drop `t.Parallel()` from the
subtests", which leaves the real hazard — global env mutation racing this file's parallel
readers — untouched.
