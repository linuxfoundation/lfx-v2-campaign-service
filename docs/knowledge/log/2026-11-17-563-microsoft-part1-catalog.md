# 2026-11-17 — #563 Microsoft part-1 inputs in the API catalog

**Docs** — `docs/api-catalog.md` now documents the six optional `microsoftConfig` inputs that #617 (Microsoft gaps part 1) added to create-campaigns: `searchPartners`, `adSchedules`, `deviceBidAdjustments` / `ageBidAdjustments` / `genderBidAdjustments`, `sharedNegativeKeywordListIds`, `structuredSnippets`, and `logoAssetId` with `logoBusinessName`. #617's description said the catalog covered them, but the rows never reached main. They are added inside the MicrosoftConfig code block, after `languages`, and each states its deployment flag (`MICROSOFT_SEARCH_NETWORK_ENABLED`, `MICROSOFT_AD_SCHEDULE_ENABLED`, `MICROSOFT_BID_ADJUSTMENTS_ENABLED`, `MICROSOFT_SHARED_NEGATIVE_LISTS_ENABLED`, `MICROSOFT_STRUCTURED_SNIPPETS_ENABLED`, `MICROSOFT_LOGO_EXTENSION_ENABLED`), its limits and what happens when it fails. Only `sharedNegativeKeywordListIds` needs `global_marketing_ops` (403, or 503 when the check cannot be made). The text started from the earlier draft on `feat/563-microsoft-gaps-v2` and was checked against main's code (`internal/platform/microsoft`, `internal/dispatch/microsoft*.go`, `internal/service/create_marketing_ops.go`). The draft had put the rows outside the code block, and it said a logo business name may not hold a control character, where the code also refuses a format character. Both are fixed here. The create-campaigns table row is unchanged, which keeps the diff small enough for GitHub to show.
