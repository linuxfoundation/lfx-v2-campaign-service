# 2026-11-14 — #587 Meta campaign naming v2 behind a flag

**Update** — The owner decided on 2026-11-14 that the business-unit naming LinkedIn adopted applies
to every paid-social platform. New Meta campaigns can now follow the same convention,
`Events | <event> | <region> | <objective> | <audienceIntent>[ <tactic>][ #<n>] | <format> | <business unit> | <funnel>`,
behind `META_NAMING_V2_ENABLED` (default off, exactly `"true"` enables it; chart value `"false"`).

- Request: optional `metaConfig.naming {region, audienceIntent, businessUnit}`, the shared
  `campaignname.Naming`, with LinkedIn's closed lists, matching and refusals: a wrong shape or a
  value off a list is a synchronous 400 (`ErrCreateConfigInvalid` pre-flight refusal from
  `PreflightCreate`, re-checked in `Dispatch` before any request) whatever the flag says, and
  `businessUnit` is required while it is on.
- Business unit: for an event campaign, the foundation that owns the event (KubeCon →
  `Cloud Native Computing Foundation (CNCF)`); `LF Events` only for an LF-run event with no
  foundation. Caller-supplied; documented in api-catalog and the design description.
- Region default: the one bucket every non-regulated geo target falls in (the GEO_TO_REGION table
  the legacy name uses, now `campaignname.CountryRegions`), else `Global`. The legacy name reports
  the FIRST country's bucket, so a US + Germany campaign moves from `NA` to `Global`.
- Intent default: `Retargeting` for the `retargeting` tactic, else `Intent` (the legacy value). A
  custom audience in `targeting` is not read as retargeting.
- Format: derived, `Static` for every creative Meta builds today (single-image or link ad; the
  legacy name said `Social`). `campaignNameFormat` is the hook where video (`Motion`) and carousel
  (`Carousel`) creatives map when those branches land.
- Unchanged: objective and funnel segments, the tactic and slot tokens inside segment 5, the ad set
  name, and every name while the flag is off.
- Retry safety: the name the claimed row records (`model.DispatchCampaignName`) is sent as
  `FrozenCampaignName` and wins over both names. Meta reuses a campaign by name only on the
  `ReconcileByName` path (dormant until LFXV2-2665 sets it); there, when nothing is frozen and no
  campaign has the v2 name, the legacy name is looked up too and a campaign found under it is
  reused under that name; a lookup that cannot settle keeps the legacy name as the partial's handle.

## Data pipeline (lf-dbt) — Meta

Meta names are parsed by the same models as LinkedIn's: `facebook_ads__campaign_report` →
`_silver_fact_campaign_report` (`ad_platform = 'facebook_ads'`) → `silver_fact_paid_ads`, which reads
an exactly-8-segment name positionally (`parse_campaign_name_position`) and falls back to keyword
macros otherwise (lf-dbt origin/main `0b6b6c15d`, read-only). Required before the flag is turned on:

1. The segment-5 strip LinkedIn already needs (` <tactic>` / ` #<n>` → the intent alone) covers Meta
   too; it is one change in `silver_fact_paid_ads` (Meta's legacy labelled names already carry them).
2. `ad_format` changes from `Social` to `Static` for v2 Meta campaigns; old campaigns keep `Social`.
   Positional parsing reports both as written, so any dashboard grouping Meta by format should
   expect both. `Carousel` is not in `parse_campaign_ad_format`'s keyword list; positional reads
   are unaffected.
3. `project` moves from the LFX slug to a canonical business unit, a fixed point of
   `normalize_project_name` that `map_paid_ads_project_id` maps; a slug no ILIKE matched before now
   lands in its foundation. Keep the two lists in step (see the LinkedIn entry).
4. `region` may change for multi-country campaigns (first country → `Global`), and `LATAM` / `India`
   are reported positionally as written.
5. `utm_term` is unaffected (Meta's is derived from the event name, not the campaign name).
6. Rollout: lf-dbt (1) → this service released with the flag off → self-serve sends `naming` →
   flip `META_NAMING_V2_ENABLED` in lfx-v2-argocd (owner approval).
