# 2026-11-16 — #563 Microsoft settle window for absent ad groups, display URL at preflight, mixed null errors

**Fix** — Three more #613 review findings. First, the bid write's reconciliation trusts a definitely-absent unconfirmed ad group only after `microsoftUnconfirmedSettleWindow` (1 hour), measured from the campaign row's `UpdatedAt`. That is the last row write, never earlier than the dispatch result that recorded the group; `CreatedAt` is the claim, before the create ran. A timed-out create can still commit, so inside the window, or when `UpdatedAt` is unknown, absence keeps the 409. A group found with a usable id still recovers at once. `MicrosoftDispatcher.bidNow` is the clock seam. Second, each requested ad group's display URL (the brief's registration domain plus its path1/path2) is now checked at the create preflight. `ValidateAdGroupDisplayURLs` is called from the new optional `service.BriefCreatePreflighter` (`MicrosoftDispatcher.PreflightCreateBrief`, run by `Orchestrator.PreflightCreateBrief` with the loaded brief, fail-open except for `ErrCreateConfigInvalid`), so an overflow is a synchronous 400. Third, `postCampaignCriterions` treats an entry with both codes explicitly null as UNCONFIRMED even beside a coded rejection, and returns the ids that were created so they are recorded for reconciliation.
