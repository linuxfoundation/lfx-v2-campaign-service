# 2026-10-15 — Account tenancy: Microsoft Ads and the five scope guards (#243)

**Docs** — closes the rest of issue #243 on top of the 2026-10-13 drift fix, which corrected the
Meta/Reddit/X rows. Checked against `origin/main` code, not the earlier tables:

- **Microsoft Ads was missing from both tenancy tables.** `docs/architecture.md` ("Account
  Tenancy", "Current Platform Accounts") and `docs/channel-connections-schema.md` ("Current Account
  Inventory") listed every other paid provider but not Microsoft, although
  `internal/bootstrap/sysacct.go` installs an LF system row for it and
  `internal/dispatch/microsoft_monitor.go` guards its account. No LF Microsoft account is recorded,
  so the tables now say its tenancy is **not yet recorded** rather than guessing a grouping.
- **The authority paragraph named two guards; there are five.** `requireLinkedInManagedAccount`,
  `requireMetaManagedAccount`, Reddit's `resolveMonitorClient`, `requireTwitterManagedAccount` and
  `requireMicrosoftManagedAccount` all return `domain.ErrAccountNotManagedByConnection`. Live only on
  LinkedIn; defensive on Meta, Reddit and X; Google Ads has none.
- **Guard lists that left out Microsoft and X** in `docs/api-catalog.md` (account-monitor row) and
  [Account-Monitor Endpoints](../architecture/account-monitor-endpoints.md) now name all five.
  The concept's "the other ad platforms share a single account" now names Meta, Reddit and X, so it
  no longer claims a shared Microsoft account.

Not changed: the code comments in `internal/dispatch/linkedin.go` ("the other ad platforms share one
account today") and `internal/service/connection.go` (lists only Reddit, LinkedIn and Meta as
emitting the sentinel) are code edits, out of scope for this docs-only change.
