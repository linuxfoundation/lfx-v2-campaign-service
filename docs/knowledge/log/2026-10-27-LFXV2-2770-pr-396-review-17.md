# 2026-10-27 — PR #396 seventeenth review: the send-time standing check sees every exclusion and every master (LFXV2-2770)

**Fix** — Greptile and Copilot findings at c2829ce4.

- `audience.StandingSendCheck` replaces `StandingCoversSend`, for dispatch and the email wizard alike:
  - it reads the filter of every send list, up to `MaxSendListFilterReads` (50); the rest keep the
    direct id check, with a warning. Attach accepts existing masters in `include_list_ids`, so a
    multi-list send can also lose a source. No send is refused for its size;
  - a send list's own NOT_IN_LIST lists count as exclusions beside the recorded suppressions, so a
    master that embeds the standing list is checked even when a wizard override supplies no
    suppressions; the early return on empty suppressions is gone;
  - the standing list is the name-search hit when that is among the exclusions; otherwise the
    exclusions are read (at most `MaxStandingCandidateReads`, 50; over that only the search hit
    counts, with a warning) and one named `LFX Standard Suppressions - …` is it, so search lag or a
    rename no longer skips the guard;
  - a send list or the standing list read back without a filter tree is
    `ErrListFilterUnreadable`: dispatch refuses before creating anything, the wizard answers 503.
