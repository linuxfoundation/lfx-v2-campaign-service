# 2026-11-16 — #563 Microsoft gaps: #613 review fixes

**Fix** — Six #613 review findings on the Microsoft create gaps, fixed together. `ValidateAdSchedules` refuses more than seven windows on any one day (Microsoft's per-day limit on day-time criteria), so preflight answers 400 before a campaign exists. The ad schedule's windows run in the Microsoft Advertising account's time zone, not `CampaignInput.TimeZone`, because the create omits `AdScheduleUseSearcherTimeZone`; the hours are still sent untranslated, and the code comments, the result step, the API catalog, the design text and the code doc now say so. The dispatcher refuses an explicit `"bidAdjustment": null` in an `adSchedules` entry and a null segment value in `deviceBidAdjustments`, `ageBidAdjustments` or `genderBidAdjustments`, which `encoding/json` would otherwise decode as a 0% adjustment; omitting the key is still allowed. A reused campaign that already has structured snippets still gets none added, but each requested snippet counts as attached only when an existing one carries its header and every value; otherwise it is counted Failed (or Unconfirmed when the lookup did not report the existing contents) and the campaign is `created_degraded`, not `created`. When a later ad group's bid write fails ambiguously (timeout, 5xx, unreadable success), the error now says that group's outcome is unconfirmed and the campaign may be partly re-bid, rather than that it "was not" re-bid.
