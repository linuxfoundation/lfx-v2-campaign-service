# 2026-11-16 — #563 Microsoft ad group reconciliation proves absence only from a fully named list

**Fix** — A #613 review finding on the bid write's reconciliation. `FindAdGroupByName` treated "no name matched" as proof that an unconfirmed later ad group is absent, even when the list held entries with no readable name (`{"Id":656}`, `null`, a null Name). Any of those may be the group it was looking for. Absence now requires every entry to carry a readable name (`lookupNamedEntityCounted` counts unnamed entries); otherwise the lookup is unestablished, the `unconfirmed` flag is kept, and the bid write keeps answering 409. The create's find-first still uses `lookupNamedEntity` unchanged: a name it could not see there is caught by Microsoft's duplicate-name refusal on the create, which the create already reconciles.
