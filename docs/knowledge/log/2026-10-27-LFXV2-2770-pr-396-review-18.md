# 2026-10-27 — PR #396 eighteenth review: static send lists, exclusions scoped to their OR branch (LFXV2-2770)

**Fix** — two regressions 099c9ba3 introduced in `audience.StandingSendCheck`, plus the matching
Copilot threads.

- Static (MANUAL, SNAPSHOT) contact lists carry no `filterBranch`, so every send to one was refused
  as unreadable, even with no suppressions. The list reader now passes `processingType`
  (`audience.ListInfo`); a static send list is checked by id only, with no source read. A DYNAMIC
  send list (or an unknown type) and the standing list still refuse without a filter tree.
- Embedded NOT_IN_LIST exclusions were pooled across send lists, and within a list across its OR
  alternatives. The standing list is now in effect per OR alternative (`orBranches`): everywhere when
  it is among the email's suppressions (and then a covered send list id refuses too), otherwise only
  in an alternative that excludes it itself; there a covered IN_LIST source refuses. In
  (IN X) OR (IN Y AND NOT S), S covering X no longer refuses; S covering Y does. The standing list is
  still found among the union of all exclusions.
- Tests (mutation-checked): `TestStandingSendCheck`, `TestHubSpot_DispatchSendsToAStaticListWithoutAFilter`,
  `TestSetWizardSendList_AppliesAStaticSendList`, `TestHubSpot_DispatchScopesAMastersOwnExclusionsToThatMaster`,
  `TestHubSpot_DispatchScopesEmbeddedExclusionsToTheirOrBranch`.
