# 2026-11-16 — #563 Microsoft temporary bid refusal, quoted-zero codes, placeholder indices, blank snippet values

**Fix** — Four #613 review findings. First, a bid write refused because an unconfirmed ad group is absent but still inside `microsoftUnconfirmedSettleWindow` now returns `settlingBidWriteError` (`internal/dispatch/bid.go`, wrapping `ErrBidUnwritable`). Its `BidSettlingReason` is a service-authored sentence naming the entry and the retry time (`UpdatedAt` + window), and `UpdateCampaignBid` maps it, before the generic `ErrBidUnwritable` text, to a 409 that says the refusal is temporary. A row with no `UpdatedAt` never settles, so it keeps the generic 409. Second, `isDefaultCode` treats a quoted `"0"` as a default, matching `isZeroCodePlaceholder`'s documentation, so `{"Index":0,"Code":"0"}` is a placeholder in keyword mutations, shared-list associations and the conversion-goal picker. Third, a zero-code placeholder clears only the slot it names. In `attribute`, one with no index or an out-of-range index (or any entry naming an out-of-range index) makes the answer unattributable, so shared-list associations without their own error are UNCONFIRMED. `keywordMutation` also treats such a placeholder-only answer as UNCONFIRMED as a whole, so a pause is not reported APPLIED and the remove is not sent. Fourth, `reportExistingSnippets` treats a null or blank entry in an existing snippet's `Values` for the requested header as UNCONFIRMED, not definitely NOT attached. Visible values that already cover the request still count as present.
