# 2026-08-05 — log/dispatch split: third review fix

**Update** — Addressed three outstanding Copilot findings on PR #80:

1. `internal/okfvalidate/validate.go` — the log-fragment filename pattern
   validated `\d{4}-\d{2}-\d{2}` digit shape only, so an impossible calendar
   date like `2026-99-99-ticket.md` passed. Now parses the captured date with
   `time.Parse("2006-01-02", ...)` and rejects it if that fails, with a new
   `TestValidateLogFragmentImpossibleCalendarDate` regression test.
2. `cmd/okfgen/main.go` / `internal/okfgen/index.go` — the generator's root
   index only emitted Architecture, Kubernetes, Code, and Specs, so re-running
   it would produce an index missing the Log entry and the OKF-deviation note
   that explains why this bundle uses `log/` instead of a single `log.md`.
   Added the Log entry to the generated index and a new `okfgen.AppendNote`
   helper to re-append the deviation note (which `WriteIndex`'s generic
   title+bullets rendering has no place for), so a re-run now reproduces the
   checked-in root index exactly.
3. `docs/knowledge/index.md` — the deviation note said a conformant `log.md`
   "can be regenerated by concatenation," but plain concatenation can't
   produce one: every fragment starts with its own H1, while the legacy
   format needs exactly one `# Log` heading with `## YYYY-MM-DD` entries
   below it. Reworded to describe normalizing each fragment's H1 into a dated
   entry under one shared heading, not concatenation.
