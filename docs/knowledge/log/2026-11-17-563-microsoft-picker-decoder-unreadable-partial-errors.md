# 2026-11-17 — #563 Microsoft picker decoder refuses unreadable or duplicated partial errors

**Fix** — Two #613 review findings on `decodeCappedList` (client.go), the streaming decoder both read-only pickers share (`ListRemarketingLists`, `ListConversionGoals`). First, a `PartialErrors` entry that was a non-null object naming no outcome, such as `{}` or `{"Code":null}`, passed both readers as clean, so an answer that did not establish a complete read could be returned as the full account list. The decoder now refuses such an entry (neither `isError` nor `isZeroCodePlaceholder`). A JSON `null` slot (padding) and an explicit zero-code placeholder still pass, and a coded entry is still refused by each reader as a partial error. Second, a key repeated under the decoder's case fold kept its last value, so `"PartialErrors":[{"Code":4119}]` followed by `"partialerrors":[]` hid the failure, and a row declaring `Id` twice could change which resource it identified. After the capped scan, so an oversized list still stops at the first row past the cap, the decoder now applies `decodeTrusted`'s identity check (`identityjson.Check`) to the whole body. Both refusals reach each reader as "not the documented shape", a 503 with nothing partial. Covered by `TestDecodeCappedList_RefusesUnreadablePartialErrorsAndDuplicateKeys`, `TestListRemarketingLists_RefusesUnreadableOrDuplicatedPartialErrors` and `TestListConversionGoals_RefusesUnreadableOrDuplicatedPartialErrors`.
