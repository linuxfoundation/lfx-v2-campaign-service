# 2026-11-16 — #563 Microsoft keyword placeholders, existing-logo comparison

**Fix** — Two more #613 review findings. First, `keywordMutation` again treats an answer whose PartialErrors holds only explicit zero-code placeholders (`{"Index":0,"Code":0,"ErrorCode":null}`, `isZeroCodePlaceholder`) as APPLIED, so a pause no longer reads UNCONFIRMED or blocks the remove that follows it. `[{}]` and `[null]` still fail closed. This repairs a regression from sharing `audienceErrorCode`'s rule in `indexedErrorItem.isError`. Second, `AttachCampaignLogo` no longer treats an existing logo as the requested one. The association read now carries the logo's `BusinessName` and `BusinessLogo`, but not its image. So a different business name is a definite failure, and a matching or unreported one is UNCONFIRMED; either way the campaign is `created_degraded` and nothing is added.
