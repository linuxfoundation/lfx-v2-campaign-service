# 2026-10-27 — PR #396 ninth review: query-identified event pages, hashed standing names, typed filters (LFXV2-2770)

**Fix** — Copilot findings at 5c27b3de.

- An event page identified by a non-tracking query ("/event?id=123") is not treated as the event's
  default audience: HubSpot's `HAS_PAGEVIEW_CONTAINS` cannot isolate it ("?id=123" also matches
  "?id=1234" and misses "?utm_source=x&id=123"). No past editions are added, a note asks the
  operator to choose editions and pages, and the prompt says so. The query stays in the EVENT url,
  the most precise visitor filter available.
- `StandardSuppressionName` cuts a too-long project id and tags it with a short hash
  (`fitTagged`, shared with `CurrentRegistrantsName`), so two long ids sharing a prefix no longer
  share a standing list. A name that fits is unchanged.
- `StandingFilterIsUnion` requires an explicit AND/OR `filterBranchType` at every node, so `{}` or a
  nested untyped node is the 409 conflict, never rewritten.
- Tests (mutation-checked): `TestInterpretCustom_AnIdentifyingEventQueryIsKeptButGetsNoDefault`,
  `TestStandardSuppressionName_LongIDsSharingAPrefixDiffer`,
  `TestStandingFilterIsUnion_RequiresATypeAtEveryNode`,
  `TestAttachExisting_UntypedStandingFilter_IsNeverRewritten`.
