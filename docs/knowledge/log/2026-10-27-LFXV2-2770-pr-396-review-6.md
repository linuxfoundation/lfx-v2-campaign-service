# 2026-10-27 — PR #396 sixth review: identifying event queries kept, repeated editions dropped before the cap (LFXV2-2770)

**Fix** — Copilot findings at 34b7b38e.

- The event URL loses only its fragment and its tracking parameters (`withoutTracking`: `utm_*`,
  `hsa_*`, `gclid`, `fbclid`, `msclkid`, `mc_cid`, `mc_eid`, `_hsenc`, `_hsmi`), not its whole
  query: "/event?id=123" names the page, and the bare "/event" filter would match every event on
  that route. `selectsPage` accepts a page-view URL only when its query equals the event URL's
  remaining query, exactly.
- `capPastEditions` drops exact repeated names before the cap. The warehouse returns distinct
  (EVENT_NAME, EVENT_ID) pairs, so one name could repeat and use up cap slots.
- Tests: `TestWithoutTracking`, `TestSelectsPage`, `TestInterpretCustom_AnIdentifyingEventQueryIsKept`,
  `TestCapPastEditions_DropsRepeatedNamesBeforeTheCap`.
