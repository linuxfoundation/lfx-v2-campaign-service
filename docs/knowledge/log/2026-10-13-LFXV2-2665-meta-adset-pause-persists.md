# 2026-10-13 — A deliberate Meta ad-set pause survives a campaign pause/resume (LFXV2-2665)

**Update** — Product decision: a pause of a Meta campaign's recorded ad set made through
`toggle-meta-ad-set-status` now survives `toggle-campaign-status` PAUSED → ACTIVE. The pause is
recorded in the campaign row's existing `result` JSON (`UserPausedAdSetID`, no migration), and a
campaign ACTIVATE on such a row calls the new `meta.Client.ActivateCampaignHoldingAdSet`: ads and
campaign activated, ad set left PAUSED. The record is written before the pause is sent (through a
new `beforeWrite` hook on `MetaAdSetStatusToggler`), so an UNCONFIRMED pause stays on record and
unknown is treated as paused. It is withdrawn when Meta definitely refused the pause, and cleared
only by a confirmed resume through the lever, so an UNCONFIRMED resume keeps it. Hand-added ad
sets and adopted rows record nothing, as before. When the record changes, the lever bumps the row
version and returns the new ETag. `list-meta-ad-sets` gains `deliberately_paused`. This replaces
the open product question in
[Meta Ad-Set Monitor and Pause/Resume](../architecture/meta-ad-sets.md).
- PR #309 review: the toggle-meta-ad-set-status contract no longer promises an ETag "also after a 503" — Goa maps the ETag header on the 200 only, so it now says an error carries no ETag and some 503 paths may still have bumped the version: re-read the campaign before retrying. The pause-marker lifecycle comment now also names withdrawal after a definitely rejected or unsent pause.
- PR #309 review: `ReplaceCampaign` now classifies a COMMIT error through `classifyCommitErr`. A COMMIT the server rejected is a confirmed rollback with no sentinel; only a lost acknowledgement (broken connection, I/O error, context ending while the answer is awaited) carries `domain.ErrWriteOutcomeUnknown`. The lever reconciles that case instead of reading it as "not recorded". It repeats the version-guarded write, and the read that proves it landed, on the CLAIMED connection, never a fresh one; only if that connection is unusable does it release the claim and re-take it first. Before, a record that landed despite its commit error suppressed the pause, leaving the ad set serving while reported deliberately paused. Now a possibly-landed record is always followed by the pause, and withdrawal and clear-on-resume are reconciled the same way (live test `TestLiveReplaceCampaignCommitErrorClasses`). The race test's channel waits are bounded and its goroutine is released on cleanup.
- PR #309 review: the meta-ad-sets concept and the api-catalog row no longer say the ETag is available on a 503 — the 200 carries it, an error carries none, and some 503 paths may still have bumped the row, so re-read before retrying.
- PR #309 review: the reconciliation no longer opens a second pooled connection while the claim pins its own (which self-starves on a saturated pool, certain with `pool_max_conns=1`). It redoes the guarded write and the read ON THE CLAIMED CONNECTION; only if that connection is unusable does it release the claim and re-take it with `ClaimCampaignVersion` before writing, each step bounded by `persistResultTimeout`. The settlement and withdrawal reads use the claim's connection too. New live tests on a one-connection pool cover the reconcile path and the fail-safe outcome, and both finish well inside the deadline.
- PR #309 review: when the pause's record could not be confirmed and Meta's answer is UNCONFIRMED or unrecognised, the record is now settled before the 503 and before the cooldown starts, so "unknown counts as paused" holds and a later campaign resume keeps the ad set paused. If the record still cannot be confirmed, the 503 says so. `ReplaceCampaign` now treats a COMMIT the server rejected (`*pgconn.PgError`, `pgx.ErrTxCommitRollback`) as a confirmed rollback, so nothing is on record and nothing is sent; `domain.ErrWriteOutcomeUnknown` now marks only a lost acknowledgement. The live tests pin both classes, and the one-connection-pool tests now use a real lost acknowledgement.
- PR #309 review: once the reconciliation gives the claim up, nothing continues without a successful re-claim. If another writer takes the claim in the gap, the lever fails closed: no pause is sent, and the 503 says the record and status are unconfirmed. Re-claimed at the original version, the first attempt is proven not to have landed, so only the new write's own ambiguous commit is "unknown" and any other failure is definite, with nothing sent. Re-claimed at the next version without the record is also definite: a 409, nothing sent. New tests cover a campaign resume taking the claim in the gap, and a live one-connection-pool rejection on the re-taken claim.
- PR #309 review: record writes and settlement reads now refuse a zero claim token (`errMetaAdSetClaimLost`), so nothing reaches `ReplaceCampaign` or `VerifyClaimedVersion` through a lock-free pooled connection once the claim is lost (`TestMetaAdSetRecord_RefusesToRunWithoutTheClaim`). The `deliberately_paused` field and the toggle description now say the record is not guaranteed after every UNCONFIRMED 503, so clients re-read it rather than assume it. The `ErrWriteOutcomeUnknown` comment now matches `classifyCommitErr`: only a lost acknowledgement, never a server-rejected commit.
- PR #309 review: a claim lost while recording AFTER Meta's confirmed answer (APPLIED or ALREADY_IN_STATE) no longer reuses the pre-write claim-loss 503, which says the status is unconfirmed and nothing was sent. The 503 now states the confirmed status outcome and reports only the deliberate-pause record as unconfirmed, telling the caller to re-read `deliberately_paused` (`TestToggleMetaAdSetStatus_ClaimLostAfterAConfirmedOutcomeReportsOnlyTheRecord`).
- PR #309 review: the record no longer makes an unconfirmed pause unsafe on resume. Before a holding campaign ACTIVATE, the dispatcher READS the held ad set's configured status from Meta. PAUSED, DELETED or ARCHIVED proceeds. ACTIVE is a definite 409 (`domain.ErrMetaHeldAdSetActive`): pause the ad set, or resume it to clear the record, through the ad-set endpoint first. The campaign toggle deliberately does not pause the ad set itself. An unreadable or mismatched ad set gets the toggle's "not modified" 503. Nothing is activated on either refusal.
- PR #309 review: `classifyCommitErr` no longer treats every COMMIT PgError as a confirmed rollback. SQLSTATEs that leave the outcome open (08007, 40003, the rest of class 08, and 57P01/57P02) carry `ErrWriteOutcomeUnknown` (`TestClassifyCommitErr`). The held-resume read now checks the ad set against the campaign's creation account when the connection's account selection was cleared, so a cleared selection no longer blocks every resume with a 503; with no account known at all it fails closed.
