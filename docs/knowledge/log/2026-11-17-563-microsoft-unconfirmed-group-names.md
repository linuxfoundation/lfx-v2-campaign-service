# 2026-11-17 — #563 Microsoft records every ad group's composed name for reconciliation

**Fix** — A Cursor Bugbot finding on #623. `createAdGroups` only copied `adGroupName` from the result `createAdGroupAndAd` returned, so a later group whose step returned no result (or one without the name) was recorded `unconfirmed` with no name. The bid write reconciles such a group by name, and `FindAdGroupByName` refuses an empty one, so `PATCH .../bid` stayed blocked for good. `createAdGroups` now composes each group's name up front, the same way the create does (`composeAdGroupName` with the group's suffix), and records it on every entry. A name the step returns still takes precedence, and an empty one never overwrites it. On the dispatch side, `reconcileMicrosoftUnaddressedAdGroups` recomposes a legacy row's missing name from a sibling entry's recorded name and suffix (`microsoft.SiblingAdGroupName`), falling back to the top-level `adGroupName`. The recomposed name is recorded together with the reconciled outcome. If no name can be recomposed, the entry is returned as `unnamed`, and `WriteBid` answers with a 409 that says a retry will not clear it and what to do instead. Tests: `TestCreateAdGroups_RecordsEveryGroupsComposedName`, `TestSiblingAdGroupName` and `TestMicrosoftAdGroups_WriteBidRecomposesALegacyUnnamedGroup`. Both the recording test and the recompose test fail without the fix.
