# 2026-11-16 — #563 Microsoft single-null error codes and unreadable PartialErrors entries

**Fix** — Two #613 review findings. First, `nestedErrorState` (`AddCampaignCriterions` for geo, ad schedule and bid adjustments) now uses the shared `codePairUnreadable` rule. An entry with one explicitly null code and the other absent (`{"Code":null}`, `{"ErrorCode":null}`) is as unreadable as both null, so beside a coded rejection the outcome is UNCONFIRMED, not a definite partial failure. The returned ids are still kept. A pair with neither key, and a null slot, stay padding there, because NestedPartialErrors is index-aligned and null-padded. Second, `attribute` (keyword mutations, shared negative-list associations) now marks an unreadable entry UNCONFIRMED instead of skipping it. An unreadable entry has explicitly null codes, is `{}`, or is an index with no code. It makes the item it names UNCONFIRMED, or every un-named item when it names none, and known failures are kept. The only positional padding in a PartialErrors array is a JSON `null` slot in a fully positional array: one entry per request item, at least one of them coded (an error or a zero-code placeholder), not truncated. `indexedErrors` records null slots so they can be told apart from `{}`. As a result, a code-less-only array (`[null]`, `[{}]`) no longer records shared lists as APPLIED, and an indexed all-null entry beside another keyword's rejection is UNCONFIRMED. `keywordMutation`'s placeholder-only check now relies on `attribute`, so a placeholder plus positional null padding is APPLIED.
