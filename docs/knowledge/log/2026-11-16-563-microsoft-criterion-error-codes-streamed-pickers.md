# 2026-11-16 — #563 Microsoft criterion error codes follow the default-code rule; picker reads stream

**Fix** — Three more #613 review findings. `postCampaignCriterions`, which the geo targets, ad schedule and bid adjustments share, now classifies its `NestedPartialErrors` with `audienceErrorCode`'s rule at both the collection and the nested `BatchErrors` level (`nestedErrorState`). A zero-code placeholder (`{"Code":0,"ErrorCode":null}`) no longer stops a fully successful create. An unreadable code (`{"Code":true}`) is a rejection, not a false success. An entry with both codes explicitly null is UNCONFIRMED, matching the keyword lever's `isZeroCodePlaceholder` rule. The remarketing-list and conversion-goal picker reads now stream their body (`decodeCappedList`), so the 5,000-row cap refuses an oversized answer at the first row past the cap, before the rest is read or allocated. The malformed-response classification is unchanged. A later ad group create that Microsoft accepted but answered with an unreadable body (`{}`, errNoID) is now recorded `unconfirmed`, so the bid write refuses for it as it does after a 5xx. `createAdGroupAndAd` wraps its UNCONFIRMED ad group, ad and keyword errors in `hierarchyStepUnconfirmedError`, so `IsOutcomeUnconfirmed` agrees with that classification.
