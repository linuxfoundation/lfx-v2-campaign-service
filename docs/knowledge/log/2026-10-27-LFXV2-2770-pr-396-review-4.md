# 2026-10-27 — PR #396 fourth review: managed suppressions hidden, resolver year rule, exact stored values (LFXV2-2770)

**Fix** — Copilot findings at b14cec05.

- `hasSuppressionHint` (so `DiscoveryHidden` and `ClassifyList`) recognises the lists the standing
  suppression flow manages: every `StandardSuppressionTerms` list, including the kernel lists, the
  `LFX Standard Suppressions - <project>` list and `<edition> - Current Registrants`. Discovery and
  reuse no longer offer them as inclusion candidates. `MatchesEventSuppression` keeps the generic
  words and excludes them, since each has its own picker row.
- `editionFamily` finds a year by the warehouse resolver's own rule (four 19xx/20xx digits bounded
  by non-digits), so "Synthetic Summit2025" is an edition of "Synthetic Summit 2026".
- `RegistrantsListMatches` requires every stored `event_name` value to equal the requested edition
  byte for byte (`eventNameValuesAre`): the QA readers it also uses trim stored values and
  intersect equalities case-insensitively, which accepted a padded value or two equalities that
  differ only in case. The QA callers are unchanged.
- Tests: `TestDiscoveryHidden_ManagedSuppressionNames`, `TestSameEventEditions`,
  `TestRegistrantsListMatches_ComparesStoredValuesExactly`.
